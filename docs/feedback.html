提交之前，先保护私人内容

GitHub Issues 是公开区域。不要上传 API Key、密码、Token、私人书籍或含个人数据的日志；截图与附件需要先脱敏。

优先描述操作与现象，只附定位问题所需的最少内容。如果问题需要私人书籍才能复现，可以先提供自己编写的短示例，不要直接公开原文件。

先看一眼已有反馈

你遇到的问题可能已经有人描述。可以先查看已有反馈，或回到用户说明确认操作方法。

官网和公开反馈可以直接浏览；提交 Issue 需要登录 GitHub。开发中的修复会明确标注状态，只有确认发布的版本才会列为用户已经收到的更新。
